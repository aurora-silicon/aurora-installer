# Aurora Alpha 27 release notes

Draft for the Alpha 27 release. This covers changes merged after [Alpha 26](https://github.com/aurora-silicon/aurora-installer/releases/tag/v0.1.0-alpha.26) was published on November 27 at 07:14 UTC. The signed installer, each distribution’s install image, and its update repository can ship different component versions. Check the signed catalog and package versions before relying on a change below.

## Upgrading an existing Aurora installation

- **Speaker protection.** Alpha 27 targets automatic migration to speakerguardd v2 through the distribution’s normal system upgrade. The migration needs the packaged v2 audio stack, the device tree for your Mac (delivered by the kernel and picked up by the Stage 2 boot update), and the matching speaker data from Apple’s macOS restore image (IPSW). End-to-end delivery for existing installations is still being verified. Once your distribution confirms the migration, install its updates together and reboot. If the built-in speakers stay muted, keep protection enabled and report your Mac model, distribution and package versions. The service keeps speakers muted when it cannot confirm that playback is safe.
- **Wi-Fi and Bluetooth on Apple N1 Macs.** Alpha 26 added firmware extraction for fresh installs. An earlier installation can still be missing the files even after a kernel upgrade. The [N1 firmware refresh](https://github.com/aurora-silicon/aurora-installer/pull/266) also needs to ship in your distribution before it can repair an existing install. Once that update is available, use Ethernet or USB tethering if needed, install the updates, and run `sudo aurora-wifi-firmware check`. If the check reports a pending update, run `sudo aurora-wifi-firmware update` and reboot. Use `sudo aurora-wifi-firmware status` to check the result. The tool fetches the firmware from the IPSW matching the installed macOS stub. If the EFI system partition is too full, the refresh stops before replacing the firmware.

## Display, graphics and input

- **14- and 16-inch OLED MacBook Pro (M5 Pro/Max).** The kernel shares the internal display setup across the four variants and adds display and brightness support where the boot display previously stayed in use. It keeps the refresh rate already set by the boot firmware to avoid a dark panel at startup. The same family gains shared trackpad haptics, Touch ID hardware descriptions, clock and SD-card setup, and writable startup variables. Touch ID still needs the matching userspace stack. [Panel support](https://github.com/aurora-silicon/linux/pull/3350) · [Refresh-rate fix](https://github.com/aurora-silicon/linux/pull/3427) · [Touch ID](https://github.com/aurora-silicon/linux/pull/3376)
- **M1, M2, M3 and M4 families.** The kernel adds or corrects board descriptions for power management, panel control, display routing and sensors. The M3 Air trackpad driver now controls its own power state. M4 graphics gains support for larger rendering tiles where the kernel and Mesa both support them. [Kernel tile support](https://github.com/aurora-silicon/linux/pull/3339) · [Mesa tile support](https://github.com/aurora-silicon/mesa/pull/1194)
- **Borealis Vulkan.** M5 GPUs gain mesh shaders, and the driver fixes device loss on workloads with many empty indirect draws. M5 Ultra support in Mesa lets Vulkan open the GPU and OpenGL applications use it through Zink, on systems with the corresponding kernel support. Across generations, Mesa improves pipeline compilation, draw and compute scheduling, and the handling of synchronization and memory. It also falls back to other Wayland buffer layouts when the preferred ones are unavailable. [Mesh shaders](https://github.com/aurora-silicon/mesa/pull/1238) · [Draw stability](https://github.com/aurora-silicon/mesa/pull/1277) · [M5 Ultra](https://github.com/aurora-silicon/mesa/pull/362) · [Wayland](https://github.com/aurora-silicon/mesa/pull/1209)

## Audio, networking and media

- **Headphones and microphones.** The desktop audio stack can switch to the headphone jack on more Macs. Microphone processing adds support for more layouts used on the MacBook Neo, newer MacBook Airs, 14-inch MacBook Pros and iMac-class machines. These changes need the matching packages and model data. [Jack routing](https://github.com/aurora-silicon/asahi-audio/pull/44) · [Jack profiles](https://github.com/aurora-silicon/alsa-ucm-conf-asahi/pull/33) · [Microphone processing](https://github.com/aurora-silicon/speakerguardd/pull/277)
- **Speaker protection.** V2 reads the playback ceiling from the sound card. The bootloader and audio stack add support for the newer T8152 platform. [Playback ceiling](https://github.com/aurora-silicon/speakerguardd/pull/222) · [Boot support](https://github.com/aurora-silicon/aura/pull/548)
- **Wi-Fi, Bluetooth and Thunderbolt.** The kernel adds N1 radio setup for the J873 family, fixes N1 startup on affected hardware, and avoids incompatible operations when scanning Thunderbolt links. [J873 radio setup](https://github.com/aurora-silicon/linux/pull/3440) · [N1 startup](https://github.com/aurora-silicon/linux/pull/3373) · [Thunderbolt](https://github.com/aurora-silicon/linux/pull/3436)
- **Media and Neural Engine.** The kernel accepts frame-based H.264 input for hardware decoding. It also extends Neural Engine firmware support and diagnostics on newer chips, including the M4 Pro MacBook Pro. Applications need compatible userspace to use these changes. [H.264](https://github.com/aurora-silicon/linux/pull/3358) · [Neural Engine](https://github.com/aurora-silicon/linux/pull/3444)

## Boot, installer and distributions

- **Boot recovery.** When a normal boot falls back to the diagnostic console, aura restarts if no diagnostic host attaches. [Boot recovery](https://github.com/aurora-silicon/aura/pull/547)
- **Installer.** The first-admin startup ownership proposal is documented as a design. Follow the current installer prompts for startup ownership. [Ownership design](https://github.com/aurora-silicon/aurora-installer/pull/252)
- **Fedora Aurora and Aurora ALARM.** Both update their kernel package for the OLED MacBook Pro changes. Fedora fixes a location-service startup timeout and prepares Fedora 45 image delivery. ALARM fixes GNOME’s handling of built-in panel brightness. [Fedora kernel](https://github.com/aurora-silicon/fedora-aurora/pull/559) · [ALARM kernel](https://github.com/aurora-silicon/alarm-aurora/pull/479) · [Fedora location service](https://github.com/aurora-silicon/fedora-aurora/pull/488) · [ALARM brightness](https://github.com/aurora-silicon/alarm-aurora/pull/475)
- **Aurora NixOS and Aurora Debian.** NixOS updates the kernel, Mesa and aura package pins. Debian updates its FEX emulator pin and adds support in the delivery pipeline for KDE Plasma, GNOME and Minimal catalogs. Debian install availability still depends on publication of the signed catalogs. [NixOS pins](https://github.com/aurora-silicon/nixos-aurora/pull/403) · [Debian emulator](https://github.com/aurora-silicon/debian-aurora/pull/15) · [Debian catalogs](https://github.com/aurora-silicon/aurora-distributions/pull/78)

## Known issues

- **Install images and updates.** Nightly installation requires a connection to the signed catalog. Features can arrive in package updates before they reach the install image. Most profiles are still awaiting physical installation qualification.
- **OLED MacBook Pro (M5 Pro/Max).** Installation requires macOS 27.2 build 26B8125 or later, subject to the installer’s firmware checks. Touchscreen firmware support and built-in speaker qualification are pending. The internal panel can stay at the refresh rate selected at startup.
- **HDR and protected video.** The kernel hides the HDR option on internal panels running macOS 27-series display firmware while HDR support is incomplete. The HDCP 2.2 change was reverted in this window. [HDR](https://github.com/aurora-silicon/linux/pull/3423) · [HDCP revert](https://github.com/aurora-silicon/linux/pull/3374)
- **External displays.** External monitor audio on the 15-inch M3 Air and 13-inch M4 Air and a dark display after sleep or reconnect on the M2 Mac mini remain open carryovers from Alpha 26. The 16-inch M3 Pro MacBook Pro still needs macOS 27.2, and GPU acceleration on the published install image needs confirmation.
- **MacBook Neo.** Update macOS to 26.6.2 or later before installing. Camera and radio firmware for this model comes from the 26.6.2 restore image.
- **Earlier Macs.** M1, M2 and most M3 Macs can still use older macOS stubs. The move to a newer stub continues by family as each is qualified.
