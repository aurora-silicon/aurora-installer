# Native firmware library

The cryptographic, sparse-range, decompression and file-verification implementation was adopted from `Engine/RestoreImage/Sources/RestoreImageCore` at Aurora installer commit `6dca86b6faf5a5387b09d6df1aad887266837bc6`. That MIT implementation credits Eryk Wieliczko’s `macos-firmware-extract`. The authenticated interoperability vectors and transport rejection fixtures retain their original bytes.

This library removes the decoder-process and full-image fallback paths. Its Swift API admits a sealed model/build recipe, publishes typed measured-range progress, checks output storage, and verifies previously published firmware before reuse. It does not launch Python or other executables. The current recipe covers J700 model-wide files from Apple’s 25G83 restore image. Per-machine calibration and complete installation orchestration remain separate work.

The original engine and CLI sources remain intact for the currently qualified installer and rollback. Remove that legacy copy when the native engine replaces every production path; it is not a second production implementation to maintain indefinitely. Current installer releases still use the old engine until that migration is qualified.

The native vendor firmware USTAR/newc/manifest writer ports the MIT interchange format from `asahi_firmware/core.py` (SHA-256 `1f1527b3a0178ea1fbf633f1aced57d78557ffb326d99f1001b5ad880a29393e`) and `asahi_firmware/cpio.py` (`cdf0058de83f2de8e9e65e5ecb6946f0ce5d57dd5e05839bf5375509964b634a`). The synthetic `package-interop.json` fixture was generated by that implementation and contains no device firmware. The writer builds archives in process and does not launch an archiver. Device collection, source admission and deployment remain separate integration work.

The native IPSW ZIP/ZIP64 reader implements bounded single-disk directory and stored/deflate member reads from the [PKWARE APPNOTE 6.3.10](https://pkware.cachefly.net/webdocs/casestudies/APPNOTE.TXT), using [zlib](https://zlib.net/manual.html) for raw deflate and CRC. Its Python-standard-library-generated synthetic fixtures include data descriptors, local ZIP64 sizes and a sparse ZIP64 archive beyond 4 GiB. This parser does not treat a ZIP checksum as cryptographic source authentication; signed source identity and authenticated AEA decoding remain separate gates.

The pure Swift `NeoRegulatoryPolicy` derives MT7932 country policies from the five authenticated restore-image tables. It ports Chris Kearney’s MIT extractor through `omacom/omarchy-mac-installer` PR #96, commit `3a7407da78c11e85d9dd1ff16a5c2f84ee68c4fe`. The all-country enumeration and input hashes follow the subsequent country-completeness fix. No firmware tables or generated policies are bundled. Output validation uses the existing public driver-format validator; the original authors and licence agreement are recorded in that PR’s `Engine/overlay/ORIGINS-mt7932-policy.md`.
