# Private M3 baseline packaging

Impact class: app capability/workspace isolation, private catalog and packaging. Linux image, image metadata and `.17` engine remain pinned and unchanged. Source base is `6f45ad29f75c606a1d0c0657f9f9809cfd23c299`. No existing baseline or encryption/Limine branch is changed.

The opt-in signed Info.plist flag `OmarchyPrivatePlainTest` is inserted only when `OMARCHY_PRIVATE_PLAIN_TEST=1` is supplied to the app packager. It disables encryption in the UI, initializes and resets the session to plain, and rejects an encrypted request at the live execution boundary. The private build hides the channel menu because every sealed channel points to the same Asahi baseline; it must not advertise an Aurora choice. Normal app builds preserve their existing behavior. Private builds use the isolated user workspace `~/Library/Application Support/com.omarchy.mx.installer.private-m3-20260922`, including catalog acceptance state, so experimental sequences cannot poison the public channel cache.

The helper service identity remains shared with the original app. The private installer package must reject an already-installed app or helper before changing either. It must not replace a user's existing helper. The default publisher identity in the generic package script is not used. The original review package is retained as evidence. The later dedicated ad-hoc delivery path below supersedes it for explicitly authorized private testing.

Validation for the original maintainer handoff covered Swift format/lint, debug and release session/catalog suites, package layout and signatures, unsupported-host guards and offline staging checks. The separate visual preview remained pending because an older simulation was open; it must not be reported as completed. No helper registration, installation, disk mutation, production signing or publication is part of this build. Production signing/notarization needs separate authorization and available credentials.

## Private ad-hoc delivery authorized September 22

The user explicitly chose a private tester build without Developer ID signing/notarization. The new impact is confined to private packaging and tests: keep the same Linux image, engine, catalog and application behavior. Build the helper first, pin its exact cdhash in the app descriptor, deny registration through the embedded development plist, seal the app, and pin its final cdhash in a separate system daemon. The helper is installed under the root-controlled `/Library/PrivilegedHelperTools` rather than a mutable app location. Existing services/state and unsupported hosts are rejected. A private postinstall verifies ownership, signatures and daemon fields before registration and does not launch the app.

Validation adds real macOS signature rejection checks and a disposable unprivileged anonymous-XPC authentication harness. No live helper registration or disk operation is required for these tests. The first installation of this candidate on Chris's M3 Pro remains an explicit experimental physical test. Open Anyway is a per-item macOS approval; the instructions must never disable Gatekeeper, strip quarantine recursively, bypass a hardware check or use a blanket command-line installer override.
