# Native payload preflight

Fresh and replacement installations check the full-OS payload in Swift before downloading firmware or launching the disk backend. The helper first prepares its signed Recovery template; this path uses that template instead of an embedded legacy Recovery app. Recovery authorization retry bypasses payload preflight, as it does firmware downloads and the backend. In-place repair retains its existing validation path.

The native gate checks the unique full-OS target, package filename, boot-chain paths, startup icon, distro/profile/layout pairing, three-partition contract, EFI population flags, required nonempty files, image capacities, 4 KiB alignment and filesystem magic. Fedora uses ext4 boot and Btrfs root; ALARM and NixOS admit their declared ext4 or Btrfs layouts. Boolean partition flags must be actual JSON Booleans. Every ZIP local record is checked, including unused entries, so links, special files, encryption, unsupported compression, local identity changes and overlapping bodies fail closed.

`IPSWArchive.readPrefix` reads at most 1 MiB of decompressed output with an independent compressed-input limit of 8 MiB, using 64 KiB chunks. The filesystem check requests only `0x11000` bytes. A partial prefix does not authenticate the remaining image: the imported catalog-bound artifact digest remains the authority for the whole archive. A complete small member also requires the declared deflate end, exact compressed/decompressed lengths and CRC. Large image bodies are never expanded to inspect a header. Record lookup and overlap limits are indexed once when opening the archive.

`test/native-payload-vectors.py` extracts the actual full-OS validation method from the source-locked backend and records 38 public synthetic positive/negative vectors. Swift tests replay them independently. Additional tests cover strict Boolean fields, metadata bounds, multi-GiB sparse stored images, a compressed 64 MiB image, input/output budgets, complete-member CRC, and unused unsafe records. `zip-prefix.json` contains a normal Python `zipfile` deflate archive of 64 one-MiB zero blocks; no expanded image is retained.

This is one execution preflight component. It does not authorize APFS changes. The backend still repeats its original checks and owns disk preparation and stub/ESP population. Strict firmware selection, source-owner admission, Neo firmware conversion/calibration and a fresh live resize/extent check must all precede any future native disk mutation. Source tests do not establish physical installation or hardware support.
